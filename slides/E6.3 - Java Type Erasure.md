# E6.3 — Java Type Erasure

## Type Erasure

**Reference — runtime model and migration compatibility.** Ordinary API use does not require reproducing the compiler transformation.
It is still legal to use collection types and other generic types without supplying type parameters, but **you should not do it**.

If you use raw types, you lose all the safety and expressiveness benefits of generics.

```java
public static void main(String[] args) {
    List l = new ArrayList();
    l.add("Hello");
    l.add("World");
    l.add(2.3);

    for (Object o : l) {
        String s = (String) o;
        // runtime error when 2.3 is processed!
        s.length();
    }
}
```

Given that you shouldn’t use raw types, why did the language designers allow them? **To provide compatibility**. 

The Java platform was about to enter its second decade when generics were introduced, and there was an enormous amount of Java code in existence that did not use generics. **It had to be legal to pass instances of parameterized types (new types) to methods that were designed for use with old types, and vice versa**. This requirement, known as *migration compatibility*, drove the decision to support raw types.

Java implements generics primarily through **erasure**: a type variable erases to its leftmost bound, or `Object` when unbounded. The compiler inserts casts and may generate bridge methods. Generic signatures can remain as metadata for reflection; erasure does not mean all generic information vanishes from class files.

You cannot use `new T[]`, `T.class`, or `instanceof List<String>` as though the element parameter were a reified runtime class. `instanceof List<?>` is permitted.

```java
public class Pair<K, V> {
    K key;
    V value;

    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() {
        return key;
    }

    public void setKey(K key) {
        this.key = key;
    }

    public V getValue() {
        return value;
    }

    public void setValue(V value) {
        this.value = value;
    }
}
```

Conceptual source-level sketch after erasure (not the literal emitted bytecode):

```java
public class Pair {
    Object key;
    Object value;

    public Pair(Object key, Object value) {
        this.key = key;
        this.value = value;
    }

    public Object getKey() {
        return key;
    }

    public void setKey(Object key) {
        this.key = key;
    }

    public Object getValue() {
        return value;
    }

    public void setValue(Object value) {
        this.value = value;
    }
}
```

In the example below, returning the smallest item of a generic list, you can see how bounded types (i.e., Measurable is the upper bound of generic type E) are erased: 

```java
public static <E extends Measurable> E min(List<E> list) {
    if (list.isEmpty()) {
        throw new IllegalArgumentException();
    }

    E smallest = list.get(0);
    for (E item : list) {
        if (item.getMeasure() < smallest.getMeasure()) {
            smallest = item;
        }
    }
    return smallest;
}
```

Conceptual source-level sketch with explicit casts:

```java
public static Measurable min(List list) {
    if (list.isEmpty()) {
        throw new IllegalArgumentException();
    }

    Measurable smallest = (Measurable) list.get(0);
    for (Object value : list) {
        Measurable item = (Measurable) value;
        if (item.getMeasure() < smallest.getMeasure()) {
            smallest = item;
        }
    }
    return smallest;
}
```
