# Java Strings

`String` represents immutable text. It provides operations for inspecting, comparing, searching, and transforming content.

All examples target **Java 25 without preview features** and build on E2.1–E2.2: references, arrays, and loops.

* **Core:** use string operations, compare content correctly, understand immutability, and read simple console input.
* **Note:** supporting details, optional on a first reading.
* **Reference:** API behavior to consult rather than memorize.

Unless a complete class is shown, place statements inside `main` and methods inside a class. Imports are shown where needed or fully qualified names are used.

## Creating and using strings

```java
public class StringBasics {
    public static void main(String[] args) {
        String text = "abc";
        System.out.println(text.length());
        System.out.println(text.toUpperCase(java.util.Locale.ROOT));
        System.out.println(text.startsWith("d"));
        System.out.println(text.indexOf('c'));
        System.out.println(text.substring(1, 3));
        System.out.println(text.equals("ABC"));
    }
}
```

Predict the six results, then run the program.

<details>
<summary>Check your prediction</summary>

The output is `3`, `ABC`, `false`, `2`, `bc`, and `false`, each on its own line.

</details>

Prefer literals for ordinary fixed text:

```java
String greeting = "hello";
String description = """
        Java strings are immutable.
        Text blocks make multiline literals easier to read.
        """;
```

A text block is still a `String`, not a separate type. It supports escapes and removes incidental indentation; the example ends with a newline.

> **Note:** `new String("hello")` creates a distinct object, but is normally unnecessary. We use it later only to make reference identity explicit.

## String main methods

**Reference — method names are less important than their contracts:**

| Method | Behavior or detail |
|---|---|
| `length()` | Number of UTF-16 code units |
| `charAt(index)` | One UTF-16 code unit at a valid index |
| `isEmpty()` | Length is zero |
| `isBlank()` | Empty or composed of whitespace code points as defined by the API |
| `equals(other)` | Same string content |
| `compareTo(other)` | Lexicographic comparison; negative, zero, or positive |
| `contains`, `startsWith`, `endsWith` | Test for literal sequences |
| `indexOf` | First matching position, or `-1` |
| `substring(begin, end)` | Begin inclusive, end exclusive |
| `replace` | Literal character or sequence replacement |
| `split` | Splitting using a regular expression |
| `strip()` | Remove leading and trailing whitespace as defined by the API |

These operations do not change the original `String`. Methods returning strings may return an existing object when appropriate; do not assume every call allocates a new one.

### Indices and boundaries

```java
String text = "Java";
System.out.println(text.substring(0, 2)); // Ja
System.out.println(text.substring(4, 4)); // Empty string
// text.charAt(4); // Throws IndexOutOfBoundsException
```

For `charAt`, `0 <= index < length()`. For `substring(begin, end)`, `0 <= begin <= end <= length()`.

**Review:** a method takes the first three units using `substring(0, 3)`. What contract should it have for shorter input? Rejecting it and accepting the whole short string are different policies; do not silently choose one without a requirement.

### Literal text versus regular expressions

```java
String filename = "report.csv";
String[] parts = filename.split("\\.");
System.out.println(java.util.Arrays.toString(parts)); // [report, csv]
System.out.println("a,b,".split(",").length);     // 2
System.out.println("a,b,".split(",", -1).length); // 3
```

`split(".")` does not mean “split on a literal dot”: `.` has a regex meaning. Default splitting discards trailing empty fields; a negative limit preserves them.

> **Note:** `replace` uses literal text, whereas `replaceAll` uses a regular expression and special replacement syntax. Regular expressions are an API topic to learn deliberately, not infer from a method name.

### Text length and Unicode

**Note — representation versus visible characters:**

```java
String symbol = "\uD83D\uDE00"; // One supplementary Unicode code point
System.out.println(symbol.length()); // 2
System.out.println(symbol.codePointCount(0, symbol.length())); // 1
```

An index addresses a UTF-16 code unit. A Unicode code point can require two units, and a user-perceived character can contain multiple code points. Neither `length()` nor code-point count universally measures visible characters.

For introductory indexing exercises, explicitly assume simple text when that is the intended scope.

## Strings in memory

**Strings are immutable:** their content cannot be modified after construction.

**Predict:** does this print `HELLO`?

```java
String original = "hello";
String alias = original;
original.toUpperCase(java.util.Locale.ROOT);
System.out.println(original);
original = original.toUpperCase(java.util.Locale.ROOT);
System.out.println(original);
System.out.println(alias);
```

<details>
<summary>Check your prediction</summary>

The outputs are `hello`, `HELLO`, and `hello`. Discarding the returned string has no effect on the original. Reassignment changes a variable, not the content of the object shared with `alias`.

</details>

### String pool

**Note:** identical string literals are interned and refer to the same `String` object. This explains identity results, but is not a rule for comparing text.

```java
String first = "Java";
String second = "Java";
String separate = new String("Java");
System.out.println(first == second);   // true: identical interned literals
System.out.println(first == separate); // false: distinct objects
```

Do not depend on how runtime text happens to be allocated or reused. Wrapper caching is a separate topic in E2.4.

## Comparing strings

* `==` compares reference identity.
* `equals` compares string content.
* `compareTo` supplies a lexicographic order, not a language-sensitive dictionary order.

```java
String expected = "Java";
String supplied = new String("Java");
System.out.println(expected == supplied);      // false
System.out.println(expected.equals(supplied)); // true
```

### Null and comparison policy

```java
String input = null;
System.out.println("yes".equals(input)); // false
System.out.println(java.util.Objects.equals(input, null)); // true
// input.equals("yes"); // Throws NullPointerException
```

`Objects.equals` compares possibly null values. It does not decide whether null is valid input for your application.

**Review:** an assistant replaces `"yes".equals(input)` with `input == "yes"` because a test using a literal passes. Add a test with `new String("yes")` and explain why the replacement is incorrect.

> **Note:** `equalsIgnoreCase` does not implement every language's text-comparison rules. Case conversion without an explicit locale uses the default locale. `Locale.ROOT` is useful for locale-independent operations; user-facing text may need an appropriate user locale and collation policy.

## Concatenating strings

### The + operator

Use `+` for a small number of values in one expression:

```java
int students = 3;
String message = "Students: " + students;
System.out.println(message); // Students: 3
```

### StringBuilder

For incremental construction in a loop, `StringBuilder` provides a mutable buffer:

```java
public class BuildText {
    public static String repeatWithConcatenation(int count) {
        String result = "";
        for (int i = 0; i < count; i++) {
            result += 'a';
        }
        return result;
    }

    public static String repeatWithBuilder(int count) {
        StringBuilder builder = new StringBuilder();
        for (int i = 0; i < count; i++) {
            builder.append('a');
        }
        return builder.toString();
    }

    public static void main(String[] args) {
        String first = repeatWithConcatenation(5);
        String second = repeatWithBuilder(5);
        System.out.println(first); // aaaaa
        System.out.println(first.equals(second)); // true
    }
}
```

These teaching methods assume a non-negative count. The builder changes during construction; the returned `String` is immutable.

Repeatedly extending an immutable accumulated result can require copying a growing amount of text. A builder avoids that pattern. This does not mean every `+` expression should be rewritten.

> **Note:** a single `nanoTime` measurement is not a reliable Java microbenchmark. JIT warm-up, allocation, garbage collection, and unused results can affect measurements. Use a suitable harness such as JMH when performance needs evidence; do not turn this introductory example into a universal timing claim.

## Standard streams

| Stream | Usual console role | Type |
|---|---|---|
| `System.in` | Input | `InputStream` |
| `System.out` | Normal output | `PrintStream` |
| `System.err` | Diagnostics | `PrintStream` |

The runtime initializes these streams. They can be redirected, so console or keyboard connections are not guaranteed.

### Printing and formatting

```java
System.out.print("Hello");
System.out.println(" world!");
System.out.printf(java.util.Locale.ROOT, "Price: %.2f%n", 12.5);
String label = String.format(java.util.Locale.ROOT, "Count: %d", 3);
System.out.println(label);
```

**Reference:** `print` adds no newline, `println` adds one, and `printf` formats output. `String.format` returns a string rather than printing it. `%n` denotes a platform line separator; `%d`, `%s`, and `%.2f` format integers, text, and two fractional digits respectively.

Formatting a rounded display does not change the stored numeric value.

## Reading from the keyboard

### Simple line input with java.lang.IO

For simple interactive programs, Java 25 provides `IO.readln` without an explicit import. Save the following as `ReadGreeting.java` and run it with `java ReadGreeting.java`:

```java
void main() {
    String name = IO.readln("Full name: ");
    if (name != null) {
        IO.println("Hello, " + name);
    }
}
```

`readln` reads a whole line without its separator and returns null at end-of-input. It returns text; numeric conversion still requires parsing. The API can throw `java.io.IOError` on an input failure.

**Core:** choose one owner and reading strategy for standard input. After using `IO.readln`, do not also read `System.in` through a scanner or another reader in the same program: buffering makes such mixing unspecified. The scanner examples below are independent programs, not additions to this one.

### Token and line input with Scanner

`Scanner` reads text and parses tokens. By default, whitespace separates tokens.

```java
import java.util.Scanner;

public class ReadName {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        System.out.print("Full name: ");
        if (scanner.hasNextLine()) {
            String name = scanner.nextLine();
            System.out.println("Hello, " + name);
        }
    }
}
```

`next()` reads one token; `nextLine()` reads the rest of the current line, excluding its line separator.

### Mixing token and line input

Use fixed input first so the behavior is reproducible:

```java
try (java.util.Scanner scanner = new java.util.Scanner("42\nAda Lovelace\n")) {
    int age = scanner.nextInt();
    String name = scanner.nextLine();
    System.out.println("[" + name + "]");
}
```

**Predict:** does `name` contain `Ada Lovelace`?

<details>
<summary>Check your prediction</summary>

No: the output is `[]`. `nextInt()` consumes the integer token but leaves the line separator. `nextLine()` consumes the empty remainder of that line.

If the input protocol puts the name on the next line, consume the remainder first, then read that next line. Alternatively, consistently read whole lines and parse the numeric lines. Do not add extra `nextLine()` calls blindly: they can discard legitimate input.

</details>

### Invalid input and ownership

* Invalid numeric tokens can cause `InputMismatchException`; missing input can also fail.
* `hasNextInt()` lets you check the next token, but an invalid token must be consumed or otherwise handled to make progress.
* Numeric parsing is locale-sensitive; set the scanner's locale when the input format requires a particular convention.

> **Note:** closing a scanner also closes its underlying source when applicable. The console demo deliberately does not close `System.in`; the application should decide its ownership. The fixed-string example uses try-with-resources, developed in E5.1.

**Reference — reading a file:**

```java
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Path;
import java.util.Scanner;

public class ReadFile {
    public static void main(String[] args) throws IOException {
        try (Scanner scanner = new Scanner(Path.of("names.txt"), StandardCharsets.UTF_8)) {
            while (scanner.hasNextLine()) {
                System.out.println(scanner.nextLine());
            }
        }
    }
}
```

The example requires a UTF-8 `names.txt` in the working directory. File errors and resource management are later topics; here, notice that a scanner can read sources other than the keyboard.
