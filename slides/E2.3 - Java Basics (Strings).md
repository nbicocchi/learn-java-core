# Java Strings

The `String` class represents character strings. A `String` is an object that represents a sequence of characters.

The `String` class provides methods for examining individual characters, comparing strings, searching within strings, extracting substrings, and creating new strings with transformed content, such as uppercase or lowercase characters.

```java
public static void main(String[] args) {
    System.out.println("abc".length());
    System.out.println("abc".toUpperCase());
    System.out.println("abc".startsWith("d"));
    System.out.println("abc".indexOf('c'));
    System.out.println("abc".substring(1, 3));
    System.out.println("abc".equals("ABC"));
}
```

We can create a string in different ways:

```java
public static void main(String[] args) {
    String a = "hello";

    String b = new String("world!");

    String c = """
            He who becomes the slave of habit,
            who follows the same routes every day,
            who never changes pace,
            who does not risk and change the color of his clothes,
            who does not speak and does not experience,
            dies slowly.
            """;
}
```

The first form uses a **string literal**. The second explicitly creates a new `String` object and is generally unnecessary when a string literal is sufficient. The third form is a **text block**, introduced in modern Java for representing multiline strings.

## String main methods

`charAt()` Returns the character at the specified index (position)

`compareTo()` Compares two strings lexicographically

`concat()` Concatenates a string to the end of another string

`contains()` Checks whether a string contains a specified sequence of characters

`endsWith()` Checks whether a string ends with the specified character sequence

`isEmpty()` Checks whether a string has length `0`

`length()` Returns the number of characters in a string

`replace()` Replaces occurrences of a specified character or character sequence and returns a new string

`split()` Splits a string into an array of substrings

`startsWith()` Checks whether a string starts with the specified character sequence

`substring()` Returns a new string containing a portion of the original string

All these methods operate on immutable `String` objects: they do not modify the original string. When a method needs to produce a different string, it returns a new `String`.

## Strings in memory

**Strings are immutable**: once a `String` object has been created, its value cannot be changed.

String literals are stored in a special area called the **string pool**. The pool allows the JVM to reuse the same `String` object for identical string literals.

```java
// String literal
String first = "Baeldung";

// Reuses the same pooled String object
String second = "Baeldung";

// true
System.out.println(first == second);
```

In this example, `first` and `second` refer to the same `String` object because both strings are the same string literal.

> **NOTE:** The `==` operator compares references, not string contents. The fact that it returns `true` here is a consequence of string-literal interning. To compare the contents of strings, use `equals()`.

When using `new String("something")`, a new `String` object is explicitly created.

```java
// New String object
String first = new String("Baeldung");

// Another new String object
String second = new String("Baeldung");

// String literal from the string pool
String third = "Baeldung";

// false
System.out.println(first == second);

// false
System.out.println(first == third);
```

In this example, `first` and `second` refer to different `String` objects even though they contain the same characters.

`third` refers to the pooled string literal, so it is also a different object from `first`.

However:

```java
System.out.println(first.equals(second)); // true
System.out.println(first.equals(third));  // true
```

because all three strings have the same content.

Because `String` is immutable, operations such as `toUpperCase()`, `replace()`, and `substring()` do not modify the original object. Instead, they return a `String` representing the result.

```java
String s = "hello";

String upper = s.toUpperCase();

System.out.println(s);     // hello
System.out.println(upper); // HELLO
```

### Integer caching

A similar optimization exists for wrapper classes such as `Integer` and is commonly known as **Integer caching**.

The Java specification guarantees caching for `Integer` values in the range **-128 to 127**. JVM implementations may cache additional values, but code should not rely on caching outside the guaranteed range.

When autoboxing or `Integer.valueOf()` is used for a cached value, the same cached object may be returned instead of creating a new object.

This can lead to apparently surprising behavior when `==` is used with wrapper objects.

```java
public class IntegerCaching {
    public static void main(String[] args) {
        for (int i = -130; i <= 130; i++) {
            System.out.println(
                i + " --> " + (Integer.valueOf(i) == Integer.valueOf(i))
            );
        }
    }
}
```

Typical output is:

```text
-130 --> false
-129 --> false
-128 --> true
-127 --> true
...
126 --> true
127 --> true
128 --> false
129 --> false
130 --> false
```

> **NOTE:** Do not use `==` to compare wrapper values. Use `equals()` when comparing the values of wrapper objects.

## Comparing strings

The **`==` operator** checks whether two references refer to the same object.

The **`equals()` method**, when correctly implemented by a class, checks whether two objects are meaningfully equal. For `String`, this means that the two strings contain the same sequence of characters.

```java
public class ComparingStrings {
    public static void checkStrings(String s1, String s2) {
        if (s1 == s2) {
            System.out.println("s1 and s2 point to the same object");
        } else {
            System.out.println("s1 and s2 point to different objects");
        }

        if (s1.equals(s2)) {
            System.out.println("s1 and s2 have the same content");
        } else {
            System.out.println("s1 and s2 have different contents");
        }
    }

    public static void main(String[] args) {
        checkStrings(
            "Hello World!",
            "Hello World!"
        ); // same object, same content

        checkStrings(
            new String("Hello World!"),
            new String("Hello World!")
        ); // different objects, same content

        checkStrings(
            new String("Hello World!"),
            new String("Hello Mars!")
        ); // different objects, different content
    }
}
```

The first call typically uses the same pooled string object because both arguments are identical string literals.

The second call explicitly creates two different objects, even though they have the same content.

The third call creates two different objects with different content.

For strings, **use `equals()` when you want to compare their contents**.

## Concatenating strings

### The `+` operator

The `+` operator can be used to concatenate two or more strings.

It can also concatenate values of other types. When one operand is a `String`, the other operand is converted to a string representation and the resulting strings are concatenated.

```java
public static void main(String[] args) {
    String s = "This string" + " is made " + "by three substrings";

    System.out.println("#students = " + 3);
    System.out.println("PI = " + 3.1415);
}
```

The output is:

```text
#students = 3
PI = 3.1415
```

The `+` operator is convenient and is generally the preferred way to concatenate a small number of strings or to build strings inside a single expression.

### StringBuilder

`String` objects are immutable. Therefore, an operation that produces a different string cannot modify the original object.

Repeated concatenation in a loop can therefore create many intermediate `String` objects. For code that performs repeated string modifications, **`StringBuilder`** provides a mutable sequence of characters and can be more efficient.

```java
import java.time.Duration;

public class ConcatenateBenchmark {
    public static String concatenateSlow(int iterations) {
        // repeated String concatenation
        String s = "";

        for (int i = 0; i < iterations; i++) {
            s += 'a';
        }

        return s;
    }

    public static String concatenateFast(int iterations) {
        // StringBuilder
        StringBuilder sb = new StringBuilder();

        for (int i = 0; i < iterations; i++) {
            sb.append('a');
        }

        return sb.toString();
    }

    public static void main(String[] args) {
        long start = System.nanoTime();

        concatenateSlow(10000);

        long end = System.nanoTime();

        System.out.println(
            "Execution time: "
                + Duration.ofNanos(end - start).toMillis()
                + "ms"
        );
    }
}
```

> **NOTE:** Modern Java compilers and JVMs can optimize some string concatenation expressions, especially when the number of operands is known at compile time. `StringBuilder` is particularly useful when building strings incrementally, for example inside loops.

`StringBuilder` is mutable, so calls such as `append()` modify the same builder object:

```java
StringBuilder sb = new StringBuilder();

sb.append("Hello");
sb.append(" ");
sb.append("World");

String result = sb.toString();

System.out.println(result); // Hello World
```

## Standard streams

Java has three standard streams commonly used to provide input to and output from Java applications:

* `System.in`
* `System.out`
* `System.err`

They are initialized by the Java runtime, so you do not normally need to instantiate these streams yourself.

* `System.in` is an `InputStream` that is typically connected to keyboard input in console programs.
* `System.out` is a `PrintStream` normally used to write output to the console or terminal.
* `System.err` is a `PrintStream` normally used to write diagnostic and error messages.

### PrintStream methods

Prints a string:

```java
void print(String s)
```

Prints a string and adds a newline:

```java
void println(String s)
```

Writes a formatted string using the specified format string and arguments:

```java
void printf(String format, Object... args)
```

Returns a formatted string using the specified format string and arguments:

```java
String String.format(String format, Object... args)
```

> **NOTE:** `String.format()` is a static method of `String`, while `print()`, `println()`, and `printf()` are methods of `PrintStream`.

## Reading from the keyboard

`Scanner` is a text scanner that can **read input and parse it into different types**, including primitive types.

It breaks its input into tokens using a delimiter pattern, which by default matches whitespace.

```java
import java.io.File;
import java.io.FileNotFoundException;
import java.util.Scanner;

public static void main(String[] args) throws FileNotFoundException {
    /* from stdin */
    Scanner scanner = new Scanner(System.in);

    String s = scanner.next();
    int i = scanner.nextInt();
    double d = scanner.nextDouble();

    /* from a file */
    Scanner scannerFile = new Scanner(new File("myNumbers"));

    while (scannerFile.hasNextLong()) {
        long aLong = scannerFile.nextLong();
    }
}
```

`next()` reads the next token, while methods such as `nextInt()`, `nextDouble()`, and `nextLong()` read a token and attempt to parse it as the corresponding type.

> **NOTE:** A `Scanner` should normally be closed when it is no longer needed. Be careful when closing a scanner created from `System.in`, because closing it also closes the underlying input stream.
