# E6.1 — Java Generic Classes and Methods

All examples target **Java 25 without preview features** and build on arrays, collections, and subtype relationships.

* **Core:** express relationships between input, stored and result types through generic classes and methods.
* **Note:** storage implementation and type inference. Bounds and wildcard capture continue in E6.2.
* **Reference:** library signatures; runtime erasure and raw-type limitations are developed in E6.3.

Examples use `java.util` types and `java.awt.Point` where a concrete unrelated type is useful; add the corresponding imports. Compile alternative class versions separately. Signature excerpts and deliberately rejected calls are labeled; they are not complete programs.

## Reuse of code and type-safety

### Integer-based resizable array

Let's start from an enhanced array for integers.

These three teaching containers expose allocated length, not a list's logical size. Setting an index beyond the current length grows storage, leaving default-valued gaps. They assume practical allocation sizes; a production implementation also needs overflow and maximum-capacity handling. Prefer standard collections for application work.

```java
public class EnhancedResizableArray {
    public static final int DEFAULT_CAPACITY = 4;
    private int[] v;

    public EnhancedResizableArray() {
        this.v = new int[DEFAULT_CAPACITY];
    }

    public int get(int index) {
        return v[index];
    }

    public void set(int index, int value) {
        if (index >= v.length) {
            int[] tmp = new int[Math.max(index + 1, v.length * 2)];
            System.arraycopy(v, 0, tmp, 0, v.length);
            v = tmp;
        }
        v[index] = value;
    }

    public boolean contains(int value) {
        for (int i : v) {
            if (i == value) {
                return true;
            }
        }
        return false;
    }

    public void fill(int value) {
        Arrays.fill(v, value);
    }

    public int[] toArray() {
        return Arrays.copyOf(v, v.length);
    }

    public int length() {
        return v.length;
    }
}
```

Writing a slightly different version of the EnhancedResizableArray class for each possible type it could manage would represent a massive violation of the **[DRY (Don't Repeat Yourself)](https://en.wikipedia.org/wiki/Don%27t_repeat_yourself)** principle.


### Object-based resizable array
To mitigate this issue we could use *Object[]* instead of *Integer[]*!

```java
public class EnhancedResizableArrayObject {
    public static final int DEFAULT_CAPACITY = 4;
    private Object[] v;

    public EnhancedResizableArrayObject() {
        this.v = new Object[DEFAULT_CAPACITY];
    }

    public Object get(int index) {
        return v[index];
    }

    public void set(int index, Object value) {
        if (index >= v.length) {
            Object[] tmp = new Object[Math.max(index + 1, v.length * 2)];
            System.arraycopy(v, 0, tmp, 0, v.length);
            v = tmp;
        }
        v[index] = value;
    }

    public boolean contains(Object value) {
        for (Object i : v) {
            if (Objects.equals(i, value)) {
                return true;
            }
        }
        return false;
    }

    public void fill(Object value) {
        Arrays.fill(v, value);
    }

    public Object[] toArray() {
        return Arrays.copyOf(v, v.length);
    }

    public int length() {
        return v.length;
    }
}

```

Now we are talking! We can store every kind of Object within the same container!

However, when we use it, the compiler complains. 

```java
public static void main(String[] args) {
    EnhancedResizableArrayObject resizableArrayObject = new EnhancedResizableArrayObject();
    resizableArrayObject.set(0, "Hello");
    resizableArrayObject.set(1, "World");
    // The compiler complains here!
    // String s = resizableArrayObject.get(0); // Deliberately rejected: Object is not String
}
```

The declared return type is `Object`. Assigning it to a `String` requires a compatible checked cast:

```java
String s = (String) resizableArrayObject.get(0);
```

There is no contract that could guarantee that the return type of the list is a *String*. The array could hold any object. It can only guarantee that it is an *Object* and therefore requires an explicit downcast to be manipulated as a string.

The cast can fail if the actual object is not a string. Adding type checks everywhere treats symptoms; a generic container can enforce the intended element type at compile time.

```java
public static void main(String[] args) {
    EnhancedResizableArrayObject resizableArrayObject = new EnhancedResizableArrayObject();
    resizableArrayObject.set(0, "Hello");
    resizableArrayObject.set(1, new Point(2,3));
    
    // Run-time error! java.lang.ClassCastException
    String s = (String)resizableArrayObject.get(1); 
}
```

### Generic resizable array
It would be much easier if programmers could express their intention to use specific types and the compiler ensured the correctness of such types. This is the core idea behind generics.

```java
List<Integer> list = new ArrayList<>();
```

`List<Integer>` declares a parameterized type. The diamond `<>` on `new ArrayList<>()` asks the compiler to infer constructor type arguments from context.

```java
public class EnhancedResizableArrayGeneric<T> {
    public static final int DEFAULT_CAPACITY = 4;
    private Object[] v;

    public EnhancedResizableArrayGeneric() {
        this.v = new Object[DEFAULT_CAPACITY];
    }

    @SuppressWarnings("unchecked")
    public T get(int index) {
        return (T) v[index];
    }

    public void set(int index, T value) {
        if (index >= v.length) {
            Object[] tmp = new Object[Math.max(index + 1, v.length * 2)];
            System.arraycopy(v, 0, tmp, 0, v.length);
            v = tmp;
        }
        v[index] = value;
    }

    public boolean contains(T value) {
        for (Object i : v) {
            if (Objects.equals(i, value)) {
                return true;
            }
        }
        return false;
    }

    public void fill(T value) {
        Arrays.fill(v, value);
    }

    public Object[] toArray() {
        return Arrays.copyOf(v, v.length);
    }

    public int length() {
        return v.length;
    }
}
```

```java
public static void main(String[] args) {
    EnhancedResizableArrayGeneric<String> resizableArrayGeneric = new EnhancedResizableArrayGeneric<>();
    resizableArrayGeneric.set(0, "Hello");
    // Compile-time error!
    // resizableArrayGeneric.set(1, new Point(2,3)); // Deliberately rejected
    
    String s = resizableArrayGeneric.get(0);
}
```

We have replaced a potential run-time error with a much safer and easier-to-handle compile-time error — a clear improvement!

### Keep unchecked operations local

The generic version uses private `Object[]` storage. Its cast is justified by an invariant: only values accepted as `T` enter through `set` and `fill`; raw-type misuse is excluded. `get` can still return null from an unfilled slot.

The `toArray` method honestly returns `Object[]`. Casting an `Object[]` to `T[]` would not create a real runtime `String[]`, and could fail at a caller expecting one. Standard collection APIs accept a destination array or array generator when a typed result is needed.

**Review:** an assistant fixes an unchecked warning by adding `@SuppressWarnings` to the entire class. Ask which invariant makes each cast safe. A warning suppression is not evidence of correctness.

## Type parameters
**A *generic type* is a class (or interface) that is parameterized over types**. To declare a generic class, we need to declare a class with the type parameter section delimited by angle brackets `<` `>` following the class name.

Remember that **only reference types can be used for generics**. This means that instead of primitive types, we use wrapper classes such as `Integer`, `Double`, `Boolean`, and so on.

This rule is unchanged in Java 25. Preview features involving primitive patterns do not introduce primitive generic type arguments or make `List<int>` legal.

```java
// Deliberately rejected:
// List<int> invalid = new ArrayList<>();

// OK!
List<Integer> list = new ArrayList<>();
```


### Single type parameter
In the following example, `Box` has a single type parameter named `T`. This is a teaching container, not `java.util.Optional`.

```java
public class Box<T> {
    private final T value;

    /**
     * Takes a value of "some type" and assigns it to the field
     */
    public Box(T t) {
        this.value = t;
    }

    /**
     * Returns a value of "some type"
     */
    public T get() {
        return value;
    }

    /**
     * Returns true is value is not null
     */
    public boolean isPresent() {
        return value != null;
    }
}

```

After being declared, a type parameter can be used inside the class body as an ordinary type. For instance, the above example uses the type parameter `T` as:

-   a type for a *field*
-   a *constructor* argument type
-   an *instance method* return type

We can now use `Box` with different types:

```java
Box<Integer> o1 = new Box<>(5);
Box<String> o2 = new Box<>("Hello!");

Integer i = o1.get();  // i = 5
String s = o2.get();   // s = "Hello!"
```

> **Note:** `java.util.Optional` has a stronger absence contract and factory methods rather than a public constructor. Its empty `get()` throws; this box's `get()` simply returns its stored value, possibly null. E7.2 develops the standard type.


### Multiple type parameters
A class can have any number of type parameters. For example, the following class has two. Most generic classes have just one or two type parameters.

```java
public class Pair<K, V> {
    K key;
    V value;

    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() {
        return key;
    }

    public void setKey(K key) {
        this.key = key;
    }

    public V getValue() {
        return value;
    }

    public void setValue(V value) {
        this.value = value;
    }
}
```

-   `T` -- Type
-   `S`, `U`, `V` etc. -- 2nd, 3rd, 4th types
-   `E` -- Element (used extensively in collections)
-   `K` -- Key
-   `V` -- Value
-   `N` -- Number

**Reference — selected Java API signatures, not complete declarations:**

```text
interface List<E> {
    boolean add(E e);
    E remove(int index);
    // ...
}

interface Map<K,V> {
    Set<K> keySet();
    Collection<V> values();
    // ...
}

class Collections {
    static <T extends Comparable<? super T>> void sort(List<T> list);
    // ...
}
```

### Type Inference
*Type inference* is a Java compiler's ability to look at each method invocation and corresponding declaration to determine the type argument (or arguments) that make the invocation applicable. 

The inference algorithm determines the types of the arguments and, if available, the type that the result is being assigned, or returned. 

Finally, the inference algorithm tries to find the **most specific** type that works with all the arguments.

```java
public class TypeInferenceWithGenerics {
    
    @SafeVarargs
    public static <T> List<T> toList(T... elements) {
        return Arrays.asList(elements);
    }

    public static void main(String[] args) {
        // the most specific type is String
        List<String> fruits = toList("apple", "banana", "cherry");
        // the most specific type is Integer
        List<Integer> numbers = toList(1, 2, 3, 4, 5);
        
        System.out.println(fruits);   // [apple, banana, cherry]
        System.out.println(numbers);  // [1, 2, 3, 4, 5]
    }
}
```

```java
import java.util.*;

class Animal {}
class Dog extends Animal {}
class Cat extends Animal {}

public class TypeInferenceExample {

    // Generic method that takes variable arguments and returns a list
    @SafeVarargs
    public static <T> List<T> toList(T... elements) {
        return Arrays.asList(elements);
    }

    public static void main(String[] args) {
        Dog dog = new Dog();
        Cat cat = new Cat();

        // Animal is the most specific type
        List<Animal> pets = toList(dog, cat);  

        System.out.println(pets);  // [Dog@..., Cat@...]
    }
}
```

## Generic Methods
### Generic static methods
**Static methods cannot use type parameters of their class!** If you want to use type parameters in a static method, declare this method's own type parameters.

```java
public static <T> T doSomething(T t) {
    return t;
}
```

```java
public static <T, U> void method(T t, U u) {
    // do something
}
```

We frequently use generic static methods for different operations with arrays and collections: sorting an array, searching for a value in a collection, reversing an array, and so on.

```text
// Selected Collections signatures, shown for reference:
public static <T> void fill(List<? super T> list, T obj);
public static <T> boolean replaceAll(List<T> list, T oldVal, T newVal);
public static void shuffle(List<?> list);
public static <T extends Comparable<? super T>> void sort(List<T> list);
```

### Generic instance methods


A generic method declares its own type parameters, independently of whether its enclosing class is generic. A method that only uses its class's `T` is not itself a generic method.

```java
// A simple generic class with type parameter T
public class SimpleClass<T> {

    // Method using the class-level type parameter T
    public T doStuff(T t) {
        return t;
    }

    // Method introducing its own type parameter U
    // Can use both the class-level T and method-level U
    public <U> T getParameterizedObject(T t, U u) {
        return t;
    }
}
```

As another example, consider the method *toArray()* defined within the java.util.List interface.

```java
interface List<E> {
    boolean add(E e);
    E remove(int index);
    <T> T[] toArray(T[] a);
    // ...
}
```

```java
public static void main(String[] args) {
    List<Integer> list = Arrays.asList(1, 2, 3, 4, 5);

    Integer[] a1 = list.toArray(new Integer[]{});
    Number[] a2 = list.toArray(new Number[]{});
    Integer[] a3 = list.toArray(Integer[]::new); // Typed array generator
}
```

The destination component type still matters: asking this integer list for `String[]` compiles through the method's independent type parameter but fails with `ArrayStoreException`. Generics do not eliminate every runtime check.
