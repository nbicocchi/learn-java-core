# E7.2 — Function Composition and Optional

## Composing behavior

```java
Predicate<Integer> nonNegative = value -> value >= 0;
Predicate<Integer> below100 = value -> value < 100;
Predicate<Integer> valid = nonNegative.and(below100);
Function<String, String> clean = String::strip;
Function<String, Integer> lengthAfterCleaning = clean.andThen(String::length);
IO.println(valid.test(50)); // true
IO.println(lengthAfterCleaning.apply(" Ada ")); // 3
```

**Note:** `IntPredicate`, `IntUnaryOperator`, and `ToIntFunction<T>` can avoid boxing in appropriate APIs. Standard `Function` and `Predicate` methods do not declare checked exceptions; a lambda cannot transparently throw an `IOException` through those contracts. Handle it meaningfully or choose an API designed to propagate it.

## Optional values
Like many programming languages, Java uses `null` to represent the absence of a value. Frequently, this approach leads to **Null Pointer Exceptions**. The British computer scientist [Tony Hoare](https://en.wikipedia.org/wiki/Tony_Hoare), the inventor of the `null` concept, even describes introducing `null` as a **"billion-dollar mistake"** since it has led to innumerable errors, vulnerabilities, and system crashes.

```java
public class App {
    record Student(String name, String lastName, String email) {}

    public static Student searchStudent(List<Student> students, String name) {
        for (Student student : students) {
            if (name.equals(student.name())) {
                return student;
            }
        }
        return null;
    }

    public static void main(String[] args) {
        List<Student> students = List.of(
                new Student("John", "Doe", "3314567543"),
                new Student("Liz", "White", "3319876543"),
                new Student("Sarah", "Green", "3317649432")
        );
        IO.println(searchStudent(students, "John").email());
        IO.println(searchStudent(students, "Josh").email()); // NPE!
    }
}
```

`Optional<T>` represents either a present non-null value or absence. An empty optional is an object, not a null reference. Never return null from a method whose contract is to return an `Optional`.

```java
public class App {
    record Student(String name, String lastName, String email) {}

    public static Optional<Student> searchStudent(List<Student> students, String name) {
        for (Student student : students) {
            if (name.equals(student.name())) {
                return Optional.of(student);
            }
        }
        return Optional.empty();
    }

    public static void main(String[] args) {
        List<Student> students = List.of(
                new Student("John", "Doe", "3314567543"),
                new Student("Liz", "White", "3319876543"),
                new Student("Sarah", "Green", "3317649432")
        );

        Optional<Student> optionalStudent = searchStudent(students, "Josh");
        if (optionalStudent.isPresent()) {
            Student student = optionalStudent.get();
            IO.println(student.email());
        }
    }
}
```

### Creating an Optional
In the following code, we create two Optional objects. The first object represents an empty value (such as `null`), and the second one keeps a string value. The `isPresent` method checks whether an object is empty or not.


```java
public static void main(String[] args) {
    Optional<String> absent = Optional.empty();
    Optional<String> present = Optional.of("Hello");

    IO.println(absent.isPresent()); // false
    IO.println(present.isPresent()); // true
}
```

In a situation when you don't know whether a variable is `null` or not, you should pass it to the `ofNullable` method instead of the `of` method. It creates an empty Optional if the passed value is `null`.


```java
public static void main(String[] args) {
    Optional<String> optMessage1 = Optional.ofNullable(null);
    Optional<String> optMessage2 = Optional.ofNullable("Hello");

    IO.println(optMessage1.isPresent()); // false
    IO.println(optMessage2.isPresent()); // true
    
}
```



### Getting the value from an Optional

The most obvious thing to do with an Optional is to get its value. 

* `get` returns the value if it's present, otherwise throws an exception;
* `orElseThrow` behaves as `get`, but the name describes it better;
* `orElse(T other)` returns the value if it's present, otherwise returns `other`;
* `orElseGet(Supplier<? extends T> other)` returns the value if it's present, otherwise invokes `other` and returns its result.

```java
public static void main(String[] args) {
    Optional<String> optName = Optional.ofNullable("John");
    Optional<String> optNull = Optional.ofNullable(null);

    IO.println(optName.get());           // "John"
    IO.println(optName.orElseThrow());   // "John"
    IO.println(optName.orElse("Default name")); // "John"
    
    // Run separately to observe failure:
    // IO.println(optNull.get());         // throws NoSuchElementException
    // IO.println(optNull.orElseThrow()); // throws NoSuchElementException
    IO.println(optNull.orElse("Default name"));   // "Default name"
}
```

### Eager and lazy defaults

**Predict:** which fallback is evaluated when a value is already present?

```java
Optional<String> name = Optional.of("Ada");
String eager = name.orElse(fallback());
String lazy = name.orElseGet(() -> fallback());
```

Use this helper in the same class:

```java
static String fallback() {
    IO.println("Computing fallback");
    return "Unknown";
}
```

### Transform an optional result

```java
Optional<String> name = Optional.of(" Ada ");
String display = name.map(String::strip)
        .filter(value -> !value.isEmpty())
        .orElse("Unknown");
IO.println(display); // Ada
```

Prefer composing an optional result when that expresses the requirement better than `isPresent` followed by `get`. Optional is primarily useful for return values representing possible absence, not an automatic replacement for every nullable field or parameter.

### Conditional actions

There are also convenient methods that take functions as arguments and perform some actions on values wrapped inside Optional:

* `ifPresent(Consumer<? super T> action)` performs the given action with the value, otherwise does nothing;
* `ifPresentOrElse(Consumer<? super T> action, Runnable emptyAction)` performs the given action with the value, otherwise performs another action.

```java
public static void main(String[] args) {
    Optional<String> optName = Optional.ofNullable("John");
    Optional<String> optNull = Optional.ofNullable(null);

    optName.ifPresent((name) -> IO.println(name.length())); // 4
    optNull.ifPresent((name) -> IO.println(name.length())); // does nothing
}
```

The "classic" equivalent of these two code snippets looks like the following. This code is more error-prone because it is possible to forget to perform the `null` check explicitly and then get the **NPE**.

```java
public static void printName(String name) {
    if (name != null) {
        IO.println(name.length());
    }
}
```

`ifPresentOrElse` expresses a two-branch action on an optional value. It does not make arbitrary code inside either branch safe or guarantee that the optional reference itself is non-null.

```java
public static void main(String[] args) {
    Optional<String> optName = Optional.ofNullable("John");
    Optional<String> optNull = Optional.ofNullable(null);

    // prints 4
    optName.ifPresentOrElse(
            (name) -> IO.println(name.length()),
            () -> IO.println(0)
    );

    // prints 0
    optNull.ifPresentOrElse(
            (name) -> IO.println(name.length()),
            () -> IO.println(0)
    );
}
```
