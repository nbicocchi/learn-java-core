# Wrapper classes

Each primitive type has a corresponding **wrapper class**.

Wrapper classes are reference types and are immutable, just like `String`.

Wrapper classes can be useful:

* when a value may be `null`;
* when you need methods or constants provided by the wrapper class, for example for converting values;
* when you need to store primitive values in generic collections, which require reference types.

The following table lists all primitive types and their corresponding wrapper classes.

| Primitive | Wrapper     |
| --------- | ----------- |
| `boolean` | `Boolean`   |
| `byte`    | `Byte`      |
| `char`    | `Character` |
| `int`     | `Integer`   |
| `float`   | `Float`     |
| `double`  | `Double`    |
| `long`    | `Long`      |
| `short`   | `Short`     |

## Boxing and unboxing

**Boxing** is the conversion of a primitive value into an object of the corresponding wrapper class.

**Unboxing** is the reverse process: converting a wrapper object into the corresponding primitive value.

Java also supports **autoboxing** and **auto-unboxing**, where the compiler performs these conversions automatically.

The following code illustrates explicit boxing and unboxing:

```java
public static void main(String[] args) {
    int primitive = 100;
    Integer reference;

    reference = Integer.valueOf(primitive);         // boxing
    int anotherPrimitive = reference.intValue();    // unboxing
}
```

The following example uses automatic conversions:

```java
public static void main(String[] args) {
    double primitive = 10.8;
    Double reference;

    reference = primitive;                          // auto-boxing
    double anotherPrimitive = reference;            // auto-unboxing
}
```

## Converting Strings to Primitive Types

Wrapper classes provide methods such as `parseInt()`, `parseDouble()`, and `parseBoolean()` for converting strings to primitive values.

```java
public static void main(String[] args) {
    String intStr = "42";
    int num = Integer.parseInt(intStr);

    String doubleStr = "3.14";
    double pi = Double.parseDouble(doubleStr);

    String boolStr = "true";
    boolean flag = Boolean.parseBoolean(boolStr);

    System.out.println("Integer: " + num);
    System.out.println("Double: " + pi);
    System.out.println("Boolean: " + flag);
}
```

For numeric parsing, invalid input generally causes a `NumberFormatException`.

For example:

```java
int number = Integer.parseInt("hello"); // NumberFormatException
```

## Converting Primitive Types to Strings

Wrapper classes provide methods such as `toString()` for converting primitive values to strings.

```java
public static void main(String[] args) {
    int number = 42;
    String intStr = Integer.toString(number);

    double pi = 3.14;
    String doubleStr = Double.toString(pi);

    boolean flag = true;
    String boolStr = Boolean.toString(flag);

    System.out.println("String from int: " + intStr);
    System.out.println("String from double: " + doubleStr);
    System.out.println("String from boolean: " + boolStr);
}
```

Another common way to convert a value to a string is:

```java
String s = String.valueOf(42);
```

## Comparing wrappers

Just like for any reference type, the operator `==` checks whether two wrapper references refer to the same object.

The `equals()` method, on the other hand, checks whether two wrapper objects are meaningfully equal, usually by comparing their values.

```java
public static void main(String[] args) {
    Long i1 = Long.valueOf("2000");
    Long i2 = Long.valueOf("2000");

    System.out.println(i1 == i2);      // false
    System.out.println(i1.equals(i2)); // true
}
```

Do not forget about this feature when working with wrappers. Even though wrapper classes correspond to primitive types, wrapper objects are **reference types**.

> **NOTE:** Wrapper classes may cache some values, so using `==` can sometimes produce `true` for equal values and sometimes `false`. Never rely on `==` for comparing wrapper values; use `equals()` instead.

## NPE when unboxing

There is one possible problem when unboxing.

If the wrapper object is `null`, unboxing it throws a **`NullPointerException`**.

```java
Long longVal = null;

long primitiveLong = longVal; // NullPointerException
```

The same problem can occur implicitly when an operation requires unboxing:

```java
Integer n1 = 50;
Integer n2 = null;

Integer result = n1 / n2; // NullPointerException
```

Before performing an operation that causes unboxing, make sure that the wrapper reference is not `null`.
