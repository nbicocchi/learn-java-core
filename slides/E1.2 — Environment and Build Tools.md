# E1.2 — Environment and Build Tools

Start with a Java 25 JDK and an editor or IDE. Verify `java -version` and `javac -version`; a build can still target an older release even when the installed runtime is newer.

To check the installation, save this compact source file as `Hello.java`:

```java
void main() {
    IO.println("Hello world!");
}
```

Run it with `java Hello.java`. The expected output is `Hello world!`.

## Building and running

![](images/basics-java-bytecode.avif)
![](images/basics-java-bytecode-jit.avif)

The compiler produces **bytecode** stored in `.class` files. The JVM loads and executes it; modern JVMs use **Just-In-Time (JIT) compilation** to translate frequently executed code into native machine code.

Distinguish three kinds of problem:

| Problem | Example | How to investigate |
|---|---|---|
| Compilation error | Undefined variable | Read the compiler diagnostic |
| Runtime failure | Integer division by zero | Read the exception and stack trace |
| Incorrect behavior | Wrong average | Compare actual results with requirements |

**A successful compilation does not establish that a program is correct.**

## History

**Reference — background, not a list of dates to memorize.**

* **1991–1996:** the Green project at Sun Microsystems led to Java's introduction and JDK 1.0.
* **2004 — Java 5:** generics, annotations, enums, and enhanced `for`.
* **2014 — Java 8:** lambdas and streams.
* **2018 / 2021 / 2023 / 2025:** Java 11, 17, 21, and 25 LTS releases.

Java has a six-month feature-release cycle. Recent LTS releases follow a two-year cadence; long-term support is provided according to the JDK vendor's policy.

These examples use Java 25 as their baseline. Compact source files, instance main methods, flexible constructor bodies, and scoped values are stable in this release. Not every feature discussed online is final: structured concurrency and primitive patterns are still preview in Java 25 and are not required by these examples.

See: [Java version history](https://en.wikipedia.org/wiki/Java_version_history), [The Java Story](https://www.youtube.com/watch?v=ZqGSg4b_cZA).

## Build tools

Compiling one file manually is simple. A project with dependencies, resources, and tests needs a repeatable build process.

* **Maven:** declarative configuration in `pom.xml`, standard directory layout, dependency management.
* **Gradle:** build configuration in Kotlin or Groovy, dependency management, incremental builds and caching.

Both can automate compilation, testing, and packaging. This repository uses **Maven**.

From a module directory containing `pom.xml`, with Maven installed:

```bash
mvn compile
mvn test
mvn package
```

These are lifecycle phases: later phases include earlier work. `package` normally includes running tests.

A successful command is only useful evidence if the expected sources were compiled and the expected tests actually ran. Read the build summary, including the test count.

> **Note:** a Java 25 example requires a compatible JDK and compiler configuration. Check `java -version`, `javac -version`, and the build's configured release: installing a newer JDK does not automatically change a project's compilation target.

### Example — build and run `tutorial_deploy`

The [tutorial_deploy module](../code/tutorial_deploy) contains a small application, a utility class and JUnit tests. From the **repository root**, build its executable JAR and run it:

```bash
mvn -f code/tutorial_deploy/pom.xml clean package
java -jar code/tutorial_deploy/target/tutorial_deploy-1.0-SNAPSHOT.jar
```

* `-f` selects the module's `pom.xml`, so there is no need to change directory.
* `clean` removes previous build output; `package` compiles the code, runs the configured test phase and creates the JAR in `target/`. Check the build summary to confirm which tests actually ran.
* The Maven Shade Plugin runs during `package` and writes `com.nbicocchi.app.App` as the JAR's entry point in its manifest. This lets `java -jar` find the application's `main` method.

The application prints:

```text
Hello World!
4
```

The filename follows the POM's artifact ID and version: `tutorial_deploy` and `1.0-SNAPSHOT`. This module currently targets Java 21 bytecode, which can also be built and run with JDK 25; running these commands does not change that target.

## Maven project structure

```text
project-root/
 ├─ pom.xml
 └─ src/
    ├─ main/
    │  ├─ java/        (application source code)
    │  └─ resources/   (non-code application resources)
    └─ test/
       ├─ java/        (test source code)
       └─ resources/   (resources used by tests)
```

* `pom.xml` defines dependencies, plugins, and build configuration.
* Resources can include configuration files or test data.

> **Note:** unit and integration tests may require different execution configuration; a directory name alone does not make a test run.

Standard conventions help IDEs, build servers, developers, and assistants work with the same project structure.

## Conventions

### Coding conventions

* **Packages:** lowercase, e.g. `com.nbicocchi.myapp`.
* **Classes and interfaces:** `UpperCamelCase`, e.g. `Point`, `List`, `Comparable`.
* **Fields, parameters, and local variables:** `lowerCamelCase`, e.g. `eventCount`.
* **Methods:** descriptive `lowerCamelCase`, e.g. `findMedian`, `distance`, `isEmpty`.
* **Constants:** typically `UPPER_SNAKE_CASE`, e.g. `MAX_SIZE`.
* **Braces:** opening brace on the declaration or statement line; closing brace on its own line.
* **Indentation:** use four spaces per level and keep formatting consistent throughout the project.
* **Spacing:** put spaces around binary operators and after commas; separate methods with a blank line.
* **Control flow:** use braces even for a single-statement `if` or loop, so later edits do not accidentally change its scope.
* **Source files:** in an ordinary source file, a public top-level class such as `ItemCounter` belongs in `ItemCounter.java`. In Maven's standard layout, its package corresponds to the directory under `src/main/java`.

Interfaces may have noun or adjective names. Getter/setter naming is common, but not every API needs getters and setters; records, for example, use component names for accessors.

Prefer names that describe meaning: `remainingCapacity` rather than `rc`, and `itemCount` rather than `n`. Boolean methods often read as questions, such as `isEmpty`, `hasNext`, or `canAccept`. Include a unit when it prevents ambiguity, for example `timeoutSeconds` instead of `timeout`.

Not every `final` field is a named constant: an instance field such as `private final String customerName` still uses `lowerCamelCase`. Uppercase names are normally reserved for fixed values such as a `static final int MAX_ITEMS`.

These are readability conventions, not all compiler requirements. For example, `ItemCounter` is a naming convention, while matching a public top-level class to its ordinary source filename is a language requirement. Follow the project's existing style and use IntelliJ **Reformat Code** (`Ctrl+Alt+L`) to apply its formatting settings.

### Example — consistent names and formatting

Save this class as `src/main/java/com/nbicocchi/myapp/ItemCounter.java` in a Maven project. It illustrates package, class, constant, field, parameter and local-variable names, together with indentation and braces. This example focuses on naming and layout, not a complete validation policy.

```java
package com.nbicocchi.myapp;

public final class ItemCounter {
    private static final int MAX_ITEMS = 100;
    private int itemCount;

    public void addItems(int quantity) {
        int remainingCapacity = MAX_ITEMS - itemCount;
        if (quantity < 0 || quantity > remainingCapacity) {
            throw new IllegalArgumentException("Quantity outside allowed range");
        }
        itemCount += quantity;
    }

    public boolean isEmpty() {
        return itemCount == 0;
    }
}
```

`MAX_ITEMS` is a shared fixed limit; `itemCount` is each object's state. `quantity` is a method parameter and `remainingCapacity` is a local variable. The names reveal their roles without abbreviations or comments that merely repeat the instructions. There is no setter for `itemCount`: callers use the operation `addItems` instead.

### Comments

```java
// A single-line comment

/*
 * A block comment
 */

/**
 * Doubles a small integer without overflowing.
 * @param number a value between -100 and 100 (caller precondition)
 * @return twice number
 */
public static int multiplyByTwo(int number) {
    return 2 * number;
}
```

![](images/basics-dont-comment-rewrite.avif)

Comments are useful for **contracts, reasons, and constraints**. Do not merely translate every statement into English. A generated comment can be wrong or become outdated just like any other comment.

Here, the documented input range is a responsibility of the caller; the method does not enforce it. Documentation and runtime validation are different things.
