# E2.4 — Java Arrays

An array is an object containing a **fixed-size sequence of elements of one component type**.

* Indices start at `0`.
* Length is fixed at creation; elements can change.
* Components can be primitive values or references.
* A multidimensional array is an array of arrays.

All examples target **Java 25 without preview features** and build on E2.2–E2.3: references, loops, and pass-by-value.

### How to use this lesson

* **Core:** create, traverse, modify, pass, and copy arrays correctly.
* **Note:** supporting details, optional on a first reading.
* **Reference:** APIs to consult, not memorize.

Unless a complete class is shown, put statements inside `main` and method declarations inside a class. Examples using `Arrays`, `List`, or `Scanner` require the corresponding `java.util` imports.

## Creating an array

### Declaration

```java
int[] numbers;
String[] names;
```

Declaring a local reference variable does not create an array or initialize that variable. Assign it before use.

### Declaration and initialization with default values

```java
int[] numbers = new int[5];
String[] names = new String[4];
```

Array elements receive default values:

| Component type | Default |
|---|---|
| Numeric primitive | `0` or `0.0` |
| `boolean` | `false` |
| `char` | `'\u0000'` |
| Reference | `null` |

`new String[4]` creates one array with four null references, not four `String` objects.

### Declaration and initialization with custom values

```java
int[] numbers = {1, 2, 3, 4, 5};
String[] names = {"John", "Mary", "David", "Sarah"};
```

### Declaration and initialization in two statements

```java
int[] numbers;
numbers = new int[]{1, 2, 3};
// numbers = {1, 2, 3}; // Does not compile outside a declaration
```

> **Note:** length zero is valid. A negative length throws `NegativeArraySizeException`. A very large allocation may fail even when its length is non-negative.

```java
int[] first = {1, 2, 3};

System.out.println(java.util.Arrays.toString(first));
```

<summary>Check your prediction</summary>

`final int[]` prevents reassigning the reference, not modifying the array's elements.

## Multi-Dimensional arrays

A two-dimensional array is an **array whose components are row-array references**.

```java
String[][] table = new String[2][3];
table[0][2] = "Mary";
```

![](images/basics-multidimensional-arrays.avif)

Rows are separate arrays and need not have the same length:

```java
int[][] matrix = {{1, 2}, {3}, {4, 5, 6}};
for (int row = 0; row < matrix.length; row++) {
    for (int column = 0; column < matrix[row].length; column++) {
        System.out.println(matrix[row][column]);
    }
}
```

Use each row's own length, not an assumed common width.

```java
int[][] rows = new int[3][];
rows[0] = new int[]{1, 2};
// rows[1] and rows[2] are still null
```

> **Note:** `new int[3][4]` creates an outer array and three row arrays initialized with zeros. It is not an uninitialized block or a guarantee of contiguous matrix storage.

### Switching rows

```java
String[][] table = {{"Alice", "Bob"}, {"Dave", "Eve"}};
String[] temporary = table[0];
table[0] = table[1];
table[1] = temporary;
```

No row contents or strings are copied: swapping row references is **O(1)**.

## Assigning and accessing elements

Valid indices satisfy:

```text
0 <= index < array.length
```

```java
import java.util.Arrays;

public class ArrayAccess {
    public static void main(String[] args) {
        int[] numbers = new int[5];
        numbers[0] = 42;
        numbers[4] = 1;
        System.out.println(Arrays.toString(numbers)); // [42, 0, 0, 0, 1]
    }
}
```

`length` is a field: use `numbers.length`, not `numbers.length()`.

An invalid index throws `ArrayIndexOutOfBoundsException`. An empty array has no valid index. Access through a null array reference throws `NullPointerException` instead.

**Review:** an assistant writes `i <= numbers.length` as a traversal condition. Which access fails for a nonempty array? What happens for an empty array?

## Iterating over an array

### Using a while loop

```java
int[] numbers = {10, 20, 30};
int index = 0;
while (index < numbers.length) {
    System.out.println(numbers[index]);
    index++;
}
```

### Using a for loop

Use indices when you need positions or want to replace elements:

```java
int[] numbers = {10, 20, 30};
for (int index = 0; index < numbers.length; index++) {
    numbers[index]++;
}
```

### Using an enhanced for loop

```java
int[] numbers = {10, 20, 30};
for (int number : numbers) {
    System.out.println(number);
}
```

**Predict:** does this alternative increment the array elements?

```java
int[] numbers = {10, 20, 30};
for (int number : numbers) {
    number++;
}
System.out.println(java.util.Arrays.toString(numbers));
```

<details>
<summary>Check your prediction</summary>

No: the output is `[10, 20, 30]`. Each iteration assigns a component value to a local variable; changing that variable does not update the component.

For reference components, the local variable contains a copied reference: mutating the referenced object can still be visible through the array.

</details>

### Filling an array from input

This complete example assumes that input tokens are valid integers and that enough values are supplied:

```java
import java.util.Arrays;
import java.util.Scanner;

public class FillArray {
    public static void main(String[] args) {
        Scanner reader = new Scanner(System.in);
        System.out.print("How many numbers (0 to 1000)? ");
        int count = reader.nextInt();
        if (count < 0 || count > 1000) {
            System.err.println("Unsupported size");
            return;
        }
        int[] numbers = new int[count];
        for (int i = 0; i < numbers.length; i++) {
            numbers[i] = reader.nextInt();
        }
        System.out.println(Arrays.toString(numbers));
    }
}
```

The application limit of 1000 is an explicit policy, not a Java limit. E2.7 develops text input; handling malformed input and resource ownership is discussed there and in later modules. This short-lived demo does not close the scanner wrapping `System.in`.

## Passing arrays to methods

An array parameter receives **a copy of the array reference**. Java is still pass-by-value.

```java
import java.util.Arrays;

public class ArrayParameters {
    public static void addOne(int[] values) {
        for (int i = 0; i < values.length; i++) {
            values[i]++;
        }
    }

    public static void replaceArray(int[] values) {
        values = new int[]{10, 20, 30};
    }

    public static void main(String[] args) {
        int[] numbers = {1, 2, 3};
        replaceArray(numbers);
        System.out.println(Arrays.toString(numbers));
        addOne(numbers);
        System.out.println(Arrays.toString(numbers));
    }
}
```

Predict both outputs, then use **Step Into** to inspect the parameter and caller references.

<details>
<summary>Check your prediction</summary>

The outputs are `[1, 2, 3]` and `[2, 3, 4]`. Reassignment affects only the parameter; element mutation affects the shared array.

</details>

If a method produces a different array, return it and let the caller explicitly assign the result.

## Array Utilities

### java.util.Arrays

**Reference — choose operations by their contract:**

| Task | API | Important detail |
|---|---|---|
| Print contents | `toString`, `deepToString` | Nested arrays need the deep form |
| Compare contents | `equals`, `deepEquals` | `==` compares array identity |
| Copy | `copyOf`, `copyOfRange` | Reference components remain references to the same objects |
| Fill | `fill` | Modifies the target array |
| Sort | `sort` | Modifies the array; ascending order for `int[]` |
| Search | `binarySearch` | Requires sorted input |
| List view | `asList` | Fixed-size view; not an independent copy |

### Copying is not assignment

```java
import java.util.Arrays;

public class CopyArray {
    public static void main(String[] args) {
        int[] source = {1, 2, 3};
        int[] copy = Arrays.copyOf(source, source.length);
        copy[0] = 99;
        System.out.println(Arrays.toString(source)); // [1, 2, 3]
        System.out.println(source == copy); // false
        System.out.println(Arrays.equals(source, copy)); // false
    }
}
```

**Review:** is `matrix.clone()` an independent copy of all rows?

```java
int[][] original = {{1, 2}, {3, 4}};
int[][] copy = original.clone();
copy[0][0] = 99;
System.out.println(original[0][0]);
```

<details>
<summary>Check your prediction</summary>

It prints `99`. Only the outer array was copied; the row arrays are shared. This is a **shallow copy**.

For an `int[][]` with non-null rows, clone each row as well when independent row contents are required. A general deep-copy policy depends on the component types and on whether shared references should be preserved.

</details>

### Sorting, searching, and printing

```java
int[] numbers = {5, 2, 8, 1, 3};
java.util.Arrays.sort(numbers);
System.out.println(java.util.Arrays.toString(numbers)); // [1, 2, 3, 5, 8]
System.out.println(java.util.Arrays.binarySearch(numbers, 5)); // 3
System.out.println(java.util.Arrays.binarySearch(numbers, 4)); // -4
```

A missing value is encoded as `-(insertionPoint) - 1`, not always `-1`. With duplicate values, the first matching index is not guaranteed. These details matter when replacing a linear search, as in E1.1.

For nested arrays:

```java
int[][] matrix = {{1, 2}, {3, 4}};
System.out.println(java.util.Arrays.deepToString(matrix)); // [[1, 2], [3, 4]]
```

### Arrays.asList

**Note — preview of collections:**

```java
String[] names = {"Alice", "Bob"};
java.util.List<String> list = java.util.Arrays.asList(names);
list.set(0, "Carol");
System.out.println(names[0]); // Carol: the view is backed by the array
// list.add("Dave"); // Throws UnsupportedOperationException
```

Fixed-size does not mean immutable. `Arrays.asList(new int[]{1, 2})` produces a list containing one `int[]`, not two boxed integers. Collections are developed in E4.1.

### System.arraycopy

Copies a range into an **existing** destination array:

```java
int[] source = {10, 20, 30, 40};
int[] destination = {0, 0, 0, 0, 0};
System.arraycopy(source, 1, destination, 2, 3);
System.out.println(java.util.Arrays.toString(destination)); // [0, 0, 20, 30, 40]
```

**Reference — argument order:** source, source position, destination, destination position, element count. Ranges must fit both arrays, and component types must be compatible. Reference elements are not cloned.

> **Note:** overlapping ranges within the same array are supported. A naive forward-copy loop is not always an equivalent replacement.

## Read, predict, verify

Before accepting an array operation, check:

* Is the reference non-null, and is the index valid?
* Is this a shared array, a view, or a copy?
* Does the operation mutate data or only reassign a local reference?
* What happens for zero elements, one element, and duplicate values?

**Exit activity:** review a proposed matrix-copy method that uses only `clone()`. Write a small example that reveals shared rows, then state what independence the caller actually needs.
