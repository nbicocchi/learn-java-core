# E5.3 — Resource Ownership

## Closing resources

When a file is opened, the JVM requests a **file descriptor** from the OS, which is a limited resource. If an exception occurs before `close()` is called, the file descriptor may not be released, potentially causing **resource leaks**. Properly closing streams ensures that system resources are freed for reuse.


```
Reader reader = null;

try {
    // code which may throw an exception
    reader = new FileReader("file.txt");
    
    reader.close();
} catch (IOException e) {
    // do something
}
```

The older **try-finally** pattern places cleanup on both normal and exceptional control-flow paths. `finally` is not literally guaranteed under every circumstance, such as abrupt JVM termination. Prefer try-with-resources for owned `AutoCloseable` resources.

```
Reader reader = null;

try {
    // code which may throw an exception
    reader = new FileReader("file.txt");
} catch (IOException e) {
    // do something
} finally {
    if (reader != null) {
        reader.close(); // Still needs an IOException policy; can mask an earlier failure.
    }
}
```



### try-with-resources
**try-with-resources** has two parts:

* **Round brackets** – declare and create one or more resources (e.g., input streams).
* **Curly brackets** – contain the code that uses these resources.

The `close()` method is automatically invoked for successfully initialized non-null resources, in reverse declaration order. A resource must implement `AutoCloseable`; closure itself can fail.



```
try (Reader reader = new FileReader("file.txt")) {
    // some code
}
```

```
try (Reader reader1 = new FileReader("file1.txt");
     Reader reader2 = new FileReader("file2.txt")) {
    // some code
}
```

**Core:** use try-with-resources for resources this scope owns. Do not close a borrowed stream merely because a helper can wrap it; for example, closing a scanner over `System.in` closes that shared input source.

```
try (Scanner scanner = new Scanner(new File("file.txt"))) {
    int first = scanner.nextInt();
    int second = scanner.nextInt();
    System.out.println("arguments: " + first + " " + second);
}
```

> **Note:** if the body and cleanup both throw, the body failure remains primary and cleanup failures are suppressed exceptions, available through `getSuppressed()`. This preserves information more reliably than a naive finally block.
