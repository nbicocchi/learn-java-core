# E4.4 — Maps

## Map Interface

A **`Map`** stores associations between **keys and values**.

A map:

* cannot contain duplicate keys
* associates each key with at most one value
* can contain duplicate values
* provides views of its keys, values, and key-value mappings

The main views are:

* `keySet()` → `Set<K>`
* `values()` → `Collection<V>`
* `entrySet()` → `Set<Map.Entry<K, V>>`

Unlike `Collection`, `Map` does not represent a collection of individual elements and therefore does not extend `Collection`.

The views are backed by the map: supported removals through them remove mappings. A `get` result of null can mean an absent key **or** a key mapped to null in implementations such as `HashMap`; use `containsKey` when that distinction matters.

**Core:** keys must remain stable with respect to equality and hashing while stored in a hash map. Mutating an equality-significant field can make a stored mapping unreachable through an ordinary lookup.

### Map main methods

For `Map<K, V>`:

* `V **put**(K key, V value)`
* `V **get**(Object key)`
* `V **remove**(Object key)`
* `boolean **containsKey**(Object key)`
* `boolean **containsValue**(Object value)`
* `Set<K> **keySet**()`
* `Collection<V> **values**()`
* `Set<Map.Entry<K, V>> **entrySet**()`
* `int **size**()`
* `boolean **isEmpty**()`
* `void **clear**()`

### Map Implementations

* **`HashMap`** implements **Map**

  * hash-table-based
  * no guaranteed iteration order
  * typically provides O(1) average-time basic operations

* **`LinkedHashMap`** extends **HashMap**

  * maintains a linked ordering between entries
  * normally preserves insertion order during iteration
  * can also be configured for access order

* **`TreeMap`** implements **NavigableMap**, which extends `SortedMap` and `Map`

  * tree-based
  * maintains keys according to an ordering
  * typically provides O(log n) basic operations

```java
public static void main(String[] args) {
    Map<Integer, String> src;

    src = new HashMap<>();
    src.put(77, "Nicola");
    src.put(17, "Marzia");
    src.put(22, "Agata");

    System.out.println(src);
    // Order is unspecified

    src = new LinkedHashMap<>();
    src.put(77, "Nicola");
    src.put(17, "Marzia");
    src.put(22, "Agata");

    System.out.println(src);
    // {77=Nicola, 17=Marzia, 22=Agata}

    src = new TreeMap<>();
    src.put(77, "Nicola");
    src.put(17, "Marzia");
    src.put(22, "Agata");

    System.out.println(src);
    // {17=Marzia, 22=Agata, 77=Nicola}
}
```

### Map initialization

```java
public static void main(String[] args) {

    /* more compact version (mutable) */
    Map<String, Integer> m =
        new HashMap<>(
            Map.of(
                "Agata", 2,
                "Marzia", 3,
                "Denise", 4,
                "Nicola", 1
            )
        );

    /* note well:
       Map.of(...) requires unique keys.

       The following code throws an IllegalArgumentException
       because "Agata" appears twice.
    */

    // Run separately to observe the failure:
    // Map.of("Agata", 2, "Agata", 3);

    /* more compact version (unmodifiable) */
    Map<String, Integer> immutable =
        Map.of(
            "Agata", 2,
            "Marzia", 3,
            "Denise", 4,
            "Nicola", 1
        );
}
```

`Map.of(...)` returns an **unmodifiable map**.

For an existing mutable map, `put` with an equal key replaces its value instead of creating a second mapping. Factory rejection of duplicate input and ordinary map update are different operations.

### Map Example

```java
public static void main(String[] args) {

    Map<String, Integer> m =
        new HashMap<>(
            Map.of(
                "Agata", 2,
                "Marzia", 3,
                "Denise", 4,
                "Nicola", 1
            )
        );

    // contains key
    if (m.containsKey("Denise")) {
        System.out.println(m.get("Denise"));
    }

    // looping keys and accessing values
    Set<String> keys = m.keySet();

    for (String key : keys) {
        System.out.println(key + " -> " + m.get(key));
    }

    // looping values
    Collection<Integer> values = m.values();

    for (int value : values) {
        System.out.println(value);
    }

    // looping entries
    for (Map.Entry<String, Integer> entry : m.entrySet()) {
        System.out.println(entry.getKey());
        System.out.println(entry.getValue());
    }
}
```

When both the key and the value are needed, iterating over `entrySet()` is generally preferable to iterating over `keySet()` and performing an additional `get()`.
