# E4.5 — Java Collection Ordering and Search

## Using `java.util.Collections`

`java.util.Collections` is a utility class containing static methods for operating on collections.

It can be thought of as a counterpart to `java.util.Arrays` for collections.

Common operations include:

* `sort()`
* `binarySearch()`
* `shuffle()`
* `reverse()`
* `rotate()`
* `min()`
* `max()`

```java
public static void main(String[] args) {

    ArrayList<String> l =
        new ArrayList<>(
            List.of("Nicola", "Agata", "Marzia", "Agata")
        );

    Collections.sort(l);
    System.out.println(l);
    // [Agata, Agata, Marzia, Nicola]

    Collections.reverse(l);
    System.out.println(l);
    // [Nicola, Marzia, Agata, Agata]

    Collections.shuffle(l);
    System.out.println(l);
    // Order is random

    Collections.rotate(l, 1);
    System.out.println(l);
    // Depends on the order before rotation

    Collections.sort(l);
    System.out.println(l);
    // [Agata, Agata, Marzia, Nicola]

    // The list must be sorted according to the same ordering
    // used by binarySearch().
    System.out.println(
        Collections.binarySearch(l, "Nicola")
    );
    // 3

    System.out.println(
        Collections.binarySearch(l, "Zane")
    );
    // -5
}
```

For `binarySearch()`:

* the list must be sorted according to the same ordering
* if the element is found, its index is returned
* if it is not found, the result is `-(insertion point) - 1`

For example, if `"Zane"` would be inserted at index `4`:

```text
-(4) - 1 = -5
```

## Sorting Collections

Objects can define a **natural ordering** by implementing the `Comparable<T>` interface.

```java
public interface Comparable<T> {
    int compareTo(T obj);
}
```

The `compareTo()` method returns:

* `< 0` if `this` precedes `obj`
* `== 0` if `this` and `obj` are considered equivalent for ordering
* `> 0` if `this` follows `obj`

A collection of `T` can be sorted according to its natural ordering when `T` implements `Comparable<? super T>`.

Many standard Java types, such as `String` and the numeric wrapper classes, implement `Comparable`.

### Sorting Example

The example below defines the natural ordering for the `Person` class as the alphabetical order of surnames.

```java
public class Person implements Comparable<Person> {

    protected String name;
    protected String lastname;
    protected int age;

    public Person(String name, String lastname, int age) {
        this.name = Objects.requireNonNull(name);
        this.lastname = Objects.requireNonNull(lastname);
        this.age = age;
    }

    @Override
    public int compareTo(Person p) {
        // order by surname
        return lastname.compareTo(p.lastname);
    }
}
```

Eventually, people with the same surname can be sorted by name as well.

```java
public class Person implements Comparable<Person> {

    protected String name;
    protected String lastname;
    protected int age;

    public Person(String name, String lastname, int age) {
        this.name = Objects.requireNonNull(name);
        this.lastname = Objects.requireNonNull(lastname);
        this.age = age;
    }

    @Override
    public int compareTo(Person p) {

        // order by surname
        int cmp = lastname.compareTo(p.lastname);

        if (cmp == 0) {
            // if surnames are equal, order by name
            cmp = name.compareTo(p.name);
        }

        return cmp;
    }
}
```

> The comparison must be consistent with the intended ordering. If `compareTo()` returns `0`, sorted collections such as `TreeSet` and `TreeMap` may treat the objects as equivalent for ordering purposes.

These examples inherit identity equality but order by names: they deliberately demonstrate that ordering equivalence is not automatically object equality. For a sorted set implementing the usual `Set` equality contract, choose an ordering consistent with `equals`.

### Comparator

Sometimes a class has a natural ordering, but an application needs to sort its objects in a different way.

For example, `Person` could have a natural ordering by surname, while a particular operation might require sorting by age.

The **`Comparator<T>`** interface allows an ordering to be defined independently of the class being compared.

```java
public interface Comparator<T> {
    int compare(T obj1, T obj2);
}
```

A `Comparator` can be implemented by a separate class:

```java
public class SortByAge implements Comparator<Person> {

    @Override
    public int compare(Person o1, Person o2) {
        return Integer.compare(o1.age, o2.age);
    }
}
```

Using `Integer.compare(...)` is preferable to subtracting the two ages directly because subtraction can overflow for arbitrary integer values.

A `Comparator` can also be provided anonymously where it is needed:

```java
public static void main(String[] args) {

    ArrayList<Person> l = new ArrayList<>();

    l.add(new Person("Mario", "Rossi", 68));
    l.add(new Person("Luca", "Bianchi", 28));
    l.add(new Person("Carlo", "Antoni", 34));

    // natural ordering (Comparable)
    Collections.sort(l);

    // Comparator with named class
    Collections.sort(l, new SortByAge());

    // Comparator with anonymous class
    Collections.sort(l, new Comparator<Person>() {

        @Override
        public int compare(Person o1, Person o2) {
            return Integer.compare(o1.age, o2.age);
        }
    });

    // Comparator with lambda
    Collections.sort(l, (o1, o2) ->
        Integer.compare(o1.age, o2.age)
    );
}
```

A lambda expression is often the most concise way to provide a comparator when the comparison logic is simple.

For example:

```java
l.sort(Comparator.comparingInt(person -> person.age));
```
